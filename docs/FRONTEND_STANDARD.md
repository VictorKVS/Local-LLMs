# Makar Frontend Standard · Local LLMs

Этот документ — учебный стандарт для роли **Makar / Frontend & Visual Systems**.

## 1. Visual direction

Рабочее название визуального языка:

> **Strict Magic / Engineering Noir**

Не «киберпанк ради киберпанка», а спокойная инженерная среда с ощущением глубины.

### Основа

- почти чёрный с холодным сине-зелёным оттенком;
- 1 главный акцент — mint/cyan;
- дополнительные статусы — blue / amber / green / red;
- тонкая сетка и мягкие radial glow;
- никакого кислотного неона на больших площадях;
- контент важнее эффектов.

## 2. Layout

Основной контейнер:

```css
max-width: 1240px;
padding-inline: 24px;
```

Поддерживаемые ширины:

- 1280–1440 — основной laptop/desktop;
- 1536–1920 — wide desktop;
- 768–1279 — tablet/small desktop;
- <768 — mobile.

Контент не растягивается на всю ширину 1920 px.

## 3. 8-point spacing

Базовый шаг: **8 px**.

Допустимые расстояния:

```text
4  / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80
```

## 4. Typography

### Display

- 48–64 px desktop;
- line-height 0.98–1.08;
- max 16–20 слов в hero.

### Page title

- 40–52 px;
- не использовать 80–100 px для обычных внутренних страниц.

### Body

- 15–17 px;
- line-height 1.55–1.7;
- длина строки: 60–75 символов.

### Metadata / mono

- 11–12 px;
- uppercase только для коротких labels.

## 5. Cards

Карточка должна иметь:

- одну доминирующую сущность;
- один статус;
- не более 2–4 вторичных метрик;
- высоту, сравнимую с соседними карточками;
- hover без прыжка layout.

## 6. Screenshot mode

Страницы должны хорошо сниматься при:

```text
Viewport: 1440 × 900
Browser zoom: 100%
URL: ?shot=1
```

В screenshot mode:

- скрывается header/footer;
- основной экран центрируется;
- остаётся только содержательная часть;
- не обрезаются ключевые карточки.

## 7. Accessibility

Минимум:

- заметный focus-ring;
- контраст текста WCAG AA;
- `prefers-reduced-motion`;
- semantic headings;
- кликабельная область nav ≥ 40 px;
- не кодировать статус только цветом.

## 8. Performance

Для учебного портала:

- без тяжёлого framework dependency;
- CSS gradients вместо огромных фоновых картинок;
- JS только для небольших интеракций;
- изображения WebP/AVIF там, где они появятся;
- Lighthouse performance target ≥ 90.

## 9. Anti-patterns

Не делать:

- заголовки, занимающие половину экрана;
- строки текста на 150+ символов;
- 6 разных акцентных цветов;
- карточки разной высоты без причины;
- декоративные blur на каждом элементе;
- маленький серый текст на почти чёрном фоне;
- таблицу там, где карточки читаются лучше;
- анимацию, мешающую сделать скриншот.

## 10. Критерий готовности

Экран считается готовым, если:

1. за 3 секунды понятно, о чём он;
2. одна главная мысль визуально доминирует;
3. всё читается на 1440×900;
4. скриншот можно вставить в отчёт без обрезки;
5. мобильная версия не разваливается;
6. визуальный стиль остаётся единым с остальными страницами.
